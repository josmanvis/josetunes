<task type="auto">
  <name>Task 1: Add publish-npm job to CI workflow</name>
  <files>.github/workflows/main.yml</files>
  <action>
Append a new `publish-npm` job to `.github/workflows/main.yml` AFTER the existing `release` job. The existing jobs (validate-version, build, release) must remain unchanged.

Add this job at the end of the `jobs:` section:

```yaml
  publish-npm:
    needs: release
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '24.x'
          registry-url: 'https://registry.npmjs.org'

      - name: Stamp version from tag
        run: |
          VERSION=${GITHUB_REF_NAME#v}
          cd packages/josetunes
          npm version $VERSION --no-git-tag-version --allow-same-version

      - name: Publish to npm
        run: |
          cd packages/josetunes
          npm publish --access public
```

CRITICAL constraints:
- Do NOT add `NODE_AUTH_TOKEN` env var anywhere -- this BREAKS OIDC authentication
- Do NOT add `--provenance` flag -- redundant with OIDC (auto-generated)
- Node version MUST be 24.x (npm 11.6.2+ required for OIDC)
- `registry-url` MUST be set in setup-node (required for OIDC auth to work)
- `id-token: write` permission is what enables OIDC token exchange
- `--access public` is needed because unscoped packages default to restricted for orgs
- `--no-git-tag-version` prevents npm from creating a new git tag
- `--allow-same-version` prevents error if package.json already has correct version
- The `needs: release` ensures npm publish only happens after GitHub Release succeeds
  </action>
