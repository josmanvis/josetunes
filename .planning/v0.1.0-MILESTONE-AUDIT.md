### Critical Issues Found

#### CRITICAL 1: npm publish missing authentication

**File:** `.github/workflows/main.yml`, line 180-183

The `npm publish` step has no `NODE_AUTH_TOKEN` environment variable. The `actions/setup-node` with `registry-url` creates an `.npmrc` expecting this token. Without it, publish will fail with 401.

**Fix required:** Add `env: NODE_AUTH_TOKEN` to the publish step. For OIDC Trusted Publishing, this should be:
```yaml
      - name: Publish to npm
        run: |
          cd packages/josetunes
          npm publish --access public --provenance
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

Or configure npm's native OIDC support if using Trusted Publishers without a token.

#### CRITICAL 2: tauri.conf.json version "0.0.0" — unverified fallback behavior

**File:** `src-tauri/tauri.conf.json`, line 10

The version is set to `"0.0.0"` with the assumption that Tauri v1 falls back to `Cargo.toml` version for artifact naming. This claim was documented in Phase 1 verification but **never empirically tested**.

**Risk:** If Tauri does NOT fall back, build artifacts will be named `josetunes_0.0.0_*.dmg/msi/deb/AppImage` instead of `josetunes_0.1.0_*`. This breaks both npm and Homebrew downloads which construct URLs with the release version.

**Fix required:** Either:
- (a) Run a test build to verify artifact naming, OR
- (b) Set `tauri.conf.json` version to match `Cargo.toml` (requires CI to stamp it from tag)
